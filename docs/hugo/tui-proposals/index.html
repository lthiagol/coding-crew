hugo — thirty proposals, eight readings

Three families of model each drew ten candidate interfaces for hugo, the TUI for the flow. Every page is a self-contained sketch on the project's own dark palette, so what you see is what the TUI would paint. Nothing is compiled; this set is for choosing a shape.

The shape is settled for all thirty: one sidebar for the configuration, one main pane for what is running, no tabs. The order is the policy and sits above the progress; the same fact is never painted twice; the crew's size is a composition (three = one per role, two = the orchestrator reviews, one = the human reviews, because an agent cannot review itself); the stamp says whether the automation runs and why; the queue carries ids and statuses, never task content — that belongs to raul.

the eight readings

Thirty sketches, but far fewer ideas. Grouped by what each one puts first, these are the readings the set contains — the convergences are the obvious ones, and the outliers are where the choice lives.

known issues

The pages are as drawn — a review round found real defects in them and the human chose not to have them fixed, so read these before picking one:

glm — the two lanes are painted inverted on all eleven pages: the agent lane wears the accent #79c0ff and the human lane the second accent #d2a8ff, the opposite of the project's palette; the accent is also spent on every claimable row instead of the focus border and the selection. The screens are CSS mockups rather than terminal drawings.

minimax — page 10 paints every count twice, and puts the code-review tasks in the human lane while a reviewer seat is live; page 04 draws a review round the record contradicts (TSK17's round 2 was already verdicted, and no further round can be in flight); every footer paints an "enter claim" key for an action that is not settled; pages 01 and 02 read alike; the index uses one off-palette colour.

deepseek — the ten pages carry no byline (the model string inside the configuration sketch is not an attribution); a held task is painted in the crew and the queue on several pages.

all three — the stamp's "why" is partial on some pages; the count of live tasks varies between sixteen and nineteen across the set (both computable — sixteen is the automation's queue, nineteen adds the three groomed); one page's ledger rows carry more than id and status.
